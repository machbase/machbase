버킷과 객체 키가 있는 주소 `s3://robot-data/episodes/part-001.parquet`를 사용합니다.
Machbase 서버가 리전·endpoint·주소 방식을 선택해 HTTP(S) 요청 주소를 만든 뒤 객체를
읽습니다. S3 호환 스토리지에는 그 스토리지의 S3 API endpoint를 지정합니다.

## 옵션 선택

| 옵션 | 값과 의미 |
|---|---|
| `source.s3.profile` | AWS 공유 파일의 프로필입니다. 생략하면 서버 `AWS_PROFILE` 또는 `default`를 사용합니다. |
| `source.s3.endpoint` | `http://host[:port]` 또는 `https://host[:port]`입니다. 계정·query·fragment가 없는 주소를 사용합니다. |
| `source.s3.region` | 서명 리전입니다. AWS 기본 HTTPS 주소도 이 값으로 구성합니다. |
| `source.s3.addressing_style` | `auto`, `path`, `virtual`입니다. 기본 `auto`는 AWS 기본 주소에 virtual, 사용자 지정 endpoint에 path를 사용합니다. |
| `source.s3.auth` | `sigv4` 또는 `anonymous`입니다. S3 URI와 서명 옵션을 쓰는 직접 URL은 기본적으로 SigV4를 선택합니다. |

`profile`은 데이터 해석 설정이며 AWS 프로필은 `source.s3.profile`로 지정합니다.
SQL에 명시한 endpoint·리전·주소 방식이 프로필의 설정보다 우선합니다. AWS 기본
endpoint를 만들거나 서명할 때 리전을 지정합니다. path 방식에서는 주소의 경로에
버킷이 들어갑니다. virtual 방식에서는 버킷이 호스트 이름 앞에 붙으므로 DNS와
HTTPS 인증서가 그 이름을 처리해야 합니다. 로컬 IP를 지정한 endpoint에는 path를 사용합니다.

## 서버 프로필과 키 선택

서버 실행 계정의 `~/.aws/config`에는 접속 설정을, `~/.aws/credentials`에는 키를 둡니다.
서버 환경의 `AWS_CONFIG_FILE`과 `AWS_SHARED_CREDENTIALS_FILE`로 경로를 바꿀 수
있습니다. 예를 들어 서울 리전의 AWS S3에는 config 파일에 다음을 설정합니다.

```ini
[profile production]
region = ap-northeast-2
s3 =
    addressing_style = virtual
```

credentials 파일에는 같은 이름의 키를 둡니다. 자리표시자는 발급받은 값으로 바꿉니다.

```ini
[production]
aws_access_key_id = <ACCESS_KEY>
aws_secret_access_key = <SECRET_KEY>
```

임시 키에는 같은 항목에 `aws_session_token`을 추가합니다. 기본 프로필은 두 파일 모두 `[default]`입니다.
실습의 `server.env`는 테스트 전용 파일과 환경변수를 구성합니다.

1. SQL에서 프로필을 지정하면 해당 프로필의 키 쌍과 선택적 토큰을 사용합니다. 없거나
   불완전하면 오류를 반환합니다.
2. SQL에서 프로필을 생략하면 서버의 `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
   선택적 `AWS_SESSION_TOKEN`을 먼저 검사합니다. 환경변수 자격증명이 없으면 선택한
   프로필의 키를 사용합니다. 환경 키 일부와 파일 키를 섞지 않습니다.
3. `anonymous` 요청에는 키와 토큰을 사용하지 않습니다. S3 옵션 없는 직접 URL은
   일반 HTTP(S) 요청으로 읽습니다.

AWS 공유 파일과 환경변수에 저장한 정적 또는 임시 키를 사용합니다. SSO, AssumeRole,
`credential_process`, EC2/ECS 자동 자격증명 검색·갱신은 지원 범위에 포함되지 않습니다.
키가 만료되면 서버의 파일이나 실행 환경을 갱신한 뒤 다시 실행합니다.

## 비공개 객체와 호환 endpoint

아래 첫 조회는 환경 키가 있어도 명시한 파일 프로필을 사용합니다. 환경 키를 사용하는
예제에서는 프로필을 생략합니다. 주소 방식을 바꾸면 실제 접속 호스트가 바뀔 수 있으므로
[일반 사용자의 endpoint 권한](../../operations/#endpoint-read-permissions)도 맞춥니다.

**S3 공유 파일의 명시 프로필로 읽기**

```sql
SELECT id, v
FROM READ(
    'source=s3://dfq-lab-data/measurements.parquet',
    'format=parquet',
    'source.s3.profile=dfq-lab',
    'source.tls.ca_file=/tmp/dfq-read-lab/ca.pem'
)
ORDER BY id;
```

**별도 프로필 지정 없이 환경의 키로 읽기**

```sql
SELECT id, v
FROM READ(
    'source=s3://dfq-lab-data/measurements.csv',
    'format=csv',
    'header=true',
    'type.id=LONG',
    'type.v=LONG',
    'source.tls.ca_file=/tmp/dfq-read-lab/ca.pem'
)
ORDER BY id;
```

**버킷을 호스트명에 넣어 읽기**

```sql
SELECT id, v
FROM READ(
    'source=s3://dfq-lab-data/measurements.csv',
    'format=csv',
    'header=true',
    'type.id=LONG',
    'type.v=LONG',
    'source.s3.profile=dfq-lab',
    'source.s3.addressing_style=virtual',
    'source.tls.ca_file=/tmp/dfq-read-lab/ca.pem'
)
ORDER BY id;
```

**직접 HTTPS 객체 주소에 SigV4 적용하기**

```sql
SELECT id, v
FROM READ(
    'source=https://localhost:19000/dfq-lab-data/measurements.csv',
    'format=csv',
    'header=true',
    'type.id=LONG',
    'type.v=LONG',
    'source.s3.profile=dfq-lab',
    'source.s3.auth=sigv4',
    'source.tls.ca_file=/tmp/dfq-read-lab/ca.pem'
)
ORDER BY id;
```

## 공개 객체와 사전 서명 URL

공개 S3 URI에는 `source.s3.auth=anonymous`를 명시합니다. 이미 완성된 HTTPS
객체 주소는 호스트·버킷·경로를 그대로 사용합니다. 완성된 주소에 `source.s3.endpoint`나
`source.s3.addressing_style`을 함께 지정하면 오류가 발생합니다.

**공개 S3 객체를 익명으로 읽기**

```sql
SELECT id, v
FROM READ(
    'source=s3://dfq-lab-public/measurements.csv',
    'format=csv',
    'header=true',
    'type.id=LONG',
    'type.v=LONG',
    'source.s3.endpoint=https://localhost:19000',
    'source.s3.region=us-east-1',
    'source.s3.auth=anonymous',
    'source.tls.ca_file=/tmp/dfq-read-lab/ca.pem'
)
ORDER BY id;
```

실습에서 발급한 URL은 `/tmp/dfq-read-lab/sql/s3.sql`의
「발급된 사전 서명 HTTPS URL로 읽기」 문장에 들어 있습니다. 이 문장을 실행하면
같은 CSV 100행을 반환합니다. 실습을 시작한 뒤 30분 이내에 실행합니다.

사전 서명된 **HTTPS** URL은 발급된 전체 주소를 `source=` 값에 전달합니다. 추가
프로필이나 SigV4 옵션을 함께 지정하지 않습니다. 서명 값은 전달받은 query 그대로
전송되지만 결과와 서버 진단에서는 query가 마스킹됩니다. 만료됐다면 유효한 URL을 다시
발급받아 새 조회에 사용합니다. JSON·envelope의 원본 표시에서 유효한 서명값을 복구할
수 없습니다. query나 fragment가 붙은 원격 URL은 VIEW 정의에 저장할 수 없습니다.

추가 실습은 `/tmp/dfq-read-lab/sql/s3.sql`에서 실행합니다. endpoint 변경, 직접 HTTPS 주소의
SigV4 인증, 객체 키 인코딩, 공개 객체 조회, 사전 서명 URL 표시를 차례로 확인할 수 있습니다.
