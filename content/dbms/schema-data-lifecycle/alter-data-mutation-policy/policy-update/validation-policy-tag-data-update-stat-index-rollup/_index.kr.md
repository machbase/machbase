현재 빌드는 TAG 실제 데이터 UPDATE를 지원하지 않습니다. 따라서 사용자가 실행할 수 있는
검증 절차는 없고, 이 페이지는 왜 `UPDATE tag SET ...` 구문이 제공되지 않는지 설명합니다.

## 배경

TAG 테이블의 시계열 데이터를 임의로 UPDATE하면, 이미 계산된 통계(stat), 인덱스(index),
롤업(rollup) 데이터가 실제 값과 불일치할 수 있습니다. 현재 빌드는 이러한 구조의
정합성을 보장하기 위해 TAG 실제 데이터 UPDATE를 허용하지 않습니다.

## 영향을 받는 내부 구조

### 통계 정보 (stat)
TAG 테이블에 `SUMMARIZED` 컬럼이 있으면 태그별 최솟값·최댓값·평균 등의 통계가 유지됩니다. 값을 UPDATE하면 통계를 재계산해야 합니다.

### 인덱스
TAG 테이블의 데이터 파티션에 구성된 인덱스가 갱신되어야 합니다.

### 롤업 (rollup)
`WITH ROLLUP` 옵션으로 생성된 TAG 테이블은 시간별 집계 데이터(롤업)를 별도로 유지합니다. 원본 값 변경 시 롤업 재계산이 필요합니다.

## 현재 권장 사항

1. **잘못된 데이터 보정**: 수정값을 새 레코드로 추가하고, 쿼리 시 보정 레코드를 우선하는 애플리케이션 로직으로 처리
2. **정정 이력 분리**: LOG/RDB 테이블에 정정 이력을 저장하고 조회 시 원본 TAG 데이터와 결합
3. **사전 검증 강화**: 수집 단계에서 값 범위, 단위, 타임스탬프를 검증하여 사후 수정 필요성을 최소화
