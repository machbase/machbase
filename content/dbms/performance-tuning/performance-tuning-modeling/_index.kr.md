Machbase에서 모델링 단계의 선택이 이후 모든 튜닝의 천장을 결정합니다. 올바른 테이블 타입과 컬럼 구조를 선택하면 인덱스·캐시·프로퍼티 조정 없이도 충분한 성능을 얻을 수 있습니다. 반대로 잘못된 모델에서 출발하면 아무리 정교한 튜닝을 적용해도 근본적인 한계를 넘기 어렵습니다.

이 섹션은 테이블 타입 선택과 스키마 설계 관점에서 성능에 직접 영향을 미치는 결정 사항들을 다룹니다.

## 왜 모델링이 성능의 기초인가

Machbase의 다섯 가지 테이블 타입은 각각 다른 저장 구조와 인덱싱 전략을 가집니다. TAG 테이블은 태그 이름과 시간을 조합한 3단계 파티션 인덱스를 자동으로 관리하여 수천 개 센서의 시계열 데이터를 고속으로 저장하고 조회합니다. LOG 테이블은 컬럼형 저장과 `_ARRIVAL_TIME` 기반 범위 스캔에 최적화되어 이벤트·로그 데이터를 효율적으로 처리합니다.

센서 계측값을 LOG 테이블에 넣으면 센서별 조회마다 전체 컬럼 스캔이 발생합니다. 반대로 이벤트 로그를 TAG 테이블에 넣으면 태그 이름 기반 파티션 구조가 의미 없어지고 메타데이터 공간이 낭비됩니다. 이 불일치는 인덱스를 아무리 추가해도 해결되지 않습니다.
