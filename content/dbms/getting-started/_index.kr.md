마크베이스는 산업 IoT 데이터 및 금융 틱 데이터와 같은 시계열 데이터를 가장 빠르고,
편리하게 처리할 수 있도록 설계된 혁신적인 시계열 데이터베이스입니다. 이 문장이 1장을
읽는 기준점입니다. 마크베이스를 이해한다는 것은 결국 “시간 순서로 빠르게 쌓이는 데이터를
어떻게 받고, 저장하고, 다시 분석할 것인가”를 이해하는 일입니다.

시계열 데이터베이스에서 시간은 단순한 컬럼이 아니라 데이터의 주축입니다. 센서 값은
측정된 시각을 잃으면 의미가 약해지고, 금융 틱은 발생 순서와 간격이 분석의 핵심이 됩니다.
따라서 시계열 DBMS는 일반적인 트랜잭션 처리보다 고속 입력, 시간 범위 조회, 집계,
다운샘플링, 보관 정책, 압축과 같은 문제를 더 앞에 둡니다. 마크베이스의 테이블 구조와
SQL 예제도 이 관점에서 읽으면 훨씬 자연스럽습니다.

처음 사용하는 DBMS는 낯선 건물에 들어서는 것과 비슷합니다. 문이 어디에 있는지,
어느 복도로 가야 하는지, 첫 방에서는 무엇을 확인해야 하는지 알면 이후의 이동이 훨씬
수월해집니다. 이 장은 Machbase DBMS의 첫 입구입니다. 서버에 접속하고, SQL을 실행하고,
테이블을 만들고, 데이터를 넣고, 다시 조회하는 가장 짧은 동선을 따라갑니다.

예제는 Machbase 서버가 `127.0.0.1:5656`에서 실행 중이고 `machsql`을 사용할 수 있다는
전제로 작성했습니다. 모든 SQL 예제는 `SYS` 사용자와 `MANAGER` 암호로 실행할 수 있습니다.
서버 준비가 아직 끝나지 않았다면 [설치, 배포, 업그레이드](/dbms/installation-deployment-upgrade/)와
[Linux Standard Edition 설치](/dbms/installation-deployment-upgrade/standard-edition/linux/)를
먼저 확인합니다.

## 실행 전제

- Machbase DBMS 서버가 `127.0.0.1:5656`에서 실행 중입니다.
- `machsql` 명령을 사용할 수 있습니다.
- 예제 SQL 파일은 `/tmp` 디렉터리에 저장되어 있다고 가정합니다.

테이블을 만드는 예제를 다시 실행하다가 `CREATE TABLE` 단계에서 이미 존재한다는 오류가
발생하면 이전 실행이 `DROP TABLE`까지 도달하지 못한 상태입니다. 해당 예제의 마지막
`DROP TABLE table_name;` 문을 한 번 실행한 뒤 다시 시작합니다. 이 장에서 검증한 서버는
`DROP TABLE IF EXISTS` 구문을 지원하지 않습니다.

## 이 장에서 확인할 것

1. Machbase DBMS가 산업 IoT와 금융 틱 같은 시계열 데이터를 위해 어떻게 설계되었는지 이해합니다.
2. `machsql`로 5656 포트에 접속합니다.
3. 시계열 데이터의 두 형태인 이벤트형 데이터와 계측값 데이터를 구분합니다.
4. LOG 테이블은 이벤트형 데이터, TAG 테이블은 태그 기반 계측값에 사용한다는 첫 기준을 확인합니다.
5. 직접 테이블을 만들고 데이터를 입력한 뒤 조회합니다.
6. 다음에 읽을 문서를 사용 목적에 맞게 선택합니다.

## 첫 확인 예제

첫 SQL은 악수와 같습니다. 산업 설비의 센서 값이든, 주식이나 선물의 틱 데이터든, 모든
처리는 먼저 데이터베이스와 정상적으로 대화할 수 있어야 시작됩니다. 다음 SQL은 현재
데이터베이스에 등록된 테이블 개수를 조회합니다.

```sql
SELECT COUNT(*) AS TABLE_COUNT FROM M$SYS_TABLES;
```

위 SQL이 `/tmp/dbms_gs_check.sql` 파일에 저장되어 있다고 가정하고 다음 명령을 실행합니다.

```bash
machsql -s 127.0.0.1 -P 5656 -u SYS -p MANAGER -f /tmp/dbms_gs_check.sql
```

정상적으로 실행되면 `TABLE_COUNT` 값이 1행으로 출력됩니다. 이 결과가 보이면 이제
Machbase DBMS와 SQL로 대화할 준비가 된 것입니다.
