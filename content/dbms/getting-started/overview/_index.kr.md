Machbase DBMS는 산업 IoT 데이터와 금융 틱 데이터처럼 시간 순서로 지속적으로 유입되는 데이터를 빠르고 효율적으로 처리하기 위한 시계열 데이터베이스입니다. 공장의 컨베이어 벨트처럼 센서 값이 쉼 없이 들어오거나, 거래소 시세처럼 짧은 간격으로 가격과 거래량이 갱신되는 환경에서는 "어디에 저장하느냐"가 성능과 운영 편의성을 좌우합니다. Machbase DBMS에서의 첫 번째 설계 결정은 데이터 성격에 맞는 테이블 유형을 선택하는 것에서 시작합니다.

시계열 데이터는 크게 두 가지 형태로 나타납니다. 첫째는 센서가 1초마다 온도를 전송하듯 규칙적인 간격으로 들어오는 계측값이고, 둘째는 주문 체결·알람 발생·로그 기록처럼 사건이 발생할 때마다 생성되는 이벤트입니다. 실제 시스템에서는 두 형태가 공존합니다. 산업 IoT 환경에서는 설비의 온도와 진동이 계측값이고 알람과 정비 이력이 이벤트이며, 금융 시스템에서는 호가·체결 틱이 빠르게 유입되고 수신 상태·처리 지연이 이벤트로 기록됩니다.

## 먼저 구분할 테이블

| 테이블 | 주 용도 | 첫 선택 기준 |
| --- | --- | --- |
| LOG | 이벤트, 로그, 이력처럼 계속 append 되는 데이터 | 산업 장비 이벤트, 금융 틱 수신 이력처럼 입력량이 많고 시간 조건으로 자주 조회합니다. |
| TAG | 센서, 설비, 계측값처럼 태그 이름과 시간축이 있는 데이터 | 태그별 시계열 조회와 집계가 중심입니다. |
| LOOKUP | 코드, 장비 메타데이터, 매핑 정보 | 작고 자주 참조되는 기준 데이터를 빠르게 조인하거나 조회합니다. |
| VOLATILE | 세션성 임시 데이터 | 서버 종료 시 사라져도 되는 메모리 데이터를 다룹니다. |

테이블 유형은 창고 안의 서로 다른 선반에 비유할 수 있습니다. LOG 선반은 시간 순서로 쌓이는 기록을, TAG 선반은 센서 이름과 시간축 기준의 계측값을 담습니다. 설비 온도 값은 TAG 테이블에 자연스럽게 어울리고, "틱을 수신했다"는 이벤트 기록은 LOG 테이블에 맞습니다. 자주 참조하는 소규모 기준표는 LOOKUP에, 관계 제약과 업무 규칙이 중요한 데이터는 RDB 테이블에 두는 것이 명확합니다. RDB 테이블은 관계형 업무 데이터와 Machbase 시계열 데이터를 함께 다루는 용도로 이후 장에서 별도로 설명합니다.

시계열 DBMS를 설계할 때는 테이블 유형과 함께 데이터 수명주기도 반드시 고려해야 합니다. 최근 원본 데이터는 높은 해상도로 신속하게 조회해야 하지만, 오래된 데이터는 집계 형태로 보관해도 충분한 경우가 많습니다. 보관 정책, 롤업, 다운샘플링, 압축은 단순한 부가 기능이 아니라 저장 비용과 조회 성능을 결정하는 핵심 설계 요소입니다.

## 개요 확인 예제

다음 예제는 LOG 테이블을 생성하고 한 행을 입력한 뒤 개수를 확인합니다. `CREATE TABLE`에 별도 유형을 지정하지 않으면 LOG 테이블이 생성됩니다. "값 하나를 넣고 다시 세어 본다"는 단순한 흐름으로, 테이블 생성부터 정리까지 기본 감각을 익힙니다.

```sql
CREATE TABLE DBMS_GS_OVERVIEW (
  TS DATETIME,
  VALUE DOUBLE
);

INSERT INTO DBMS_GS_OVERVIEW
VALUES (TO_DATE('2026-07-02 00:00:00', 'YYYY-MM-DD HH24:MI:SS'), 1.5);

SELECT COUNT(*) AS ROW_COUNT FROM DBMS_GS_OVERVIEW;

DROP TABLE DBMS_GS_OVERVIEW;
```

위 SQL이 `/tmp/dbms_gs_overview.sql` 파일에 저장되어 있다고 가정하고 다음 명령을 실행합니다.

```bash
machsql -s 127.0.0.1 -P 5656 -u SYS -p MANAGER -f /tmp/dbms_gs_overview.sql
```

`ROW_COUNT`가 `1`이면 생성, 입력, 조회, 삭제가 모두 정상적으로 수행된 것입니다. 작은 쿼리 하나가 안정적으로 동작해야 더 큰 적재와 분석도 신뢰할 수 있습니다. 재실행 중 `DBMS_GS_OVERVIEW`가 이미 존재한다는 오류가 나면 `DROP TABLE DBMS_GS_OVERVIEW;`를 실행한 뒤 다시 시작합니다.
