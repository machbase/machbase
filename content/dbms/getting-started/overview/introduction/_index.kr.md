Machbase DBMS는 산업 IoT 데이터와 금융 틱 데이터 같은 시계열 데이터를 고속으로 처리하도록 설계된 시계열 데이터베이스입니다. 사용자는 익숙한 SQL로 테이블을 만들고 데이터를 조회하지만, 내부적으로는 테이블 유형에 따라 입력, 저장, 조회 특성이 다르게 동작합니다. 겉으로 같은 SQL처럼 보여도 어떤 테이블에 담느냐에 따라 데이터가 정리되는 방식이 달라집니다.

일반적인 업무 데이터는 특정 레코드를 정확히 찾아 수정하거나 여러 테이블을 조인하는 일이 중심입니다. 반면 시계열 데이터는 대부분 계속 추가되고, 시간 범위로 읽히며, 평균·최대·최소·합계 같은 집계를 통해 의미를 얻습니다. "지난 10분 동안 온도가 어떻게 변했는가", "장 마감 직전 틱이 얼마나 몰렸는가", "지난 한 달간 설비 알람이 어느 시간대에 집중되었는가"처럼 시간 흐름을 따라가는 질문이 시계열 데이터베이스의 본령입니다.

## 핵심 관점

- 데이터가 지속적으로 유입된다면 LOG 테이블을 먼저 검토합니다. 애플리케이션 로그, 이벤트 이력, 장비 상태 기록, 금융 틱 수신 로그가 대표적입니다.
- 태그 이름, 시간, 값의 구조가 명확하다면 TAG 테이블을 먼저 검토합니다. "어느 태그가, 어느 시각에, 어떤 값을 가졌는가"가 핵심인 온도 센서 값 같은 데이터에 적합합니다.
- 소규모의 조회 중심 기준 정보는 LOOKUP을 먼저 검토합니다. 장비 코드와 장비명의 매핑처럼 자주 참조하는 작은 기준표로 활용할 수 있습니다.
- 관계형 업무 엔터티와 변경이 중요한 기준 정보는 RDB 계열 문서를 검토합니다. RDB 테이블은 RDB 지원 버전의 Standard Edition에서 `CREATE RDB TABLE`로 생성합니다.
- 서버 재시작 시 소멸해도 무방한 임시 작업 데이터는 VOLATILE 테이블을 사용합니다.

이 관점은 Machbase를 처음 배울 때 특히 중요합니다. 시계열 데이터베이스의 기본 단위는 "현재 값 하나"가 아니라 "시간을 따라 이어지는 값의 흐름"입니다. 스키마를 설계할 때도 컬럼 목록만 볼 것이 아니라 입력 속도, 시간 조건, 집계 단위, 보관 기간, 기준 정보와의 관계를 함께 고려해야 합니다.

처음에는 모든 테이블 유형을 직접 만들어 볼 필요가 없습니다. [10분 빠른 시작](../../quick-start/)의 LOG 테이블 예제로 SQL 흐름을 확인한 뒤, 데이터 성격에 맞춰 TAG, LOOKUP, RDB, VOLATILE 문서를 차례로 읽으면 됩니다. `SHOW TABLES` 결과에 `_TAG_DATA_`처럼 밑줄로 시작하는 `KEYVALUE` 테이블이 보일 수 있는데, 이는 TAG 테이블을 위해 DBMS가 내부적으로 관리하는 테이블이므로 첫 설계 대상에서 제외합니다.
