<span class="badge-since">Available since Machbase 8.7.0</span>

`ROWID` is a 64-bit identifier for locating a row in a table. A supported SDK can return the ROWID
after a successful single-row SQL INSERT so the application can confirm or retrieve that row without
another search.

This feature requires supported server and SDK versions in Standard Edition. It is not available in
Cluster Edition.

## ROWID is not a business key

- `ROWID` is not included in `SELECT *`; select it explicitly.
- Do not compare ROWIDs from different tables.
- Do not decompose a ROWID or infer global insertion order from its numeric value.
- Do not define a new physical column named `ROWID`.
- A legacy physical `ROWID` column takes precedence until it is renamed.

```sql
SELECT ROWID, name, time, value
  FROM sensor_tag
 WHERE name = 'TAG-01';
```

## Support by table type

| Table | Meaning | Query condition | Single INSERT result |
|---|---|---|---|
| LOG | Stored log-row identifier | Comparison, `BETWEEN`, and `ORDER BY` | Generated ROWID |
| TAG | Stored raw TAG-row identifier | One top-level `ROWID = value` condition | Generated ROWID |
| TRANSACTION | Single nonnegative `LONG`/`INT64` primary key | Existing PK conditions | PK value |
| LOOKUP | Single nonnegative `LONG`/`INT64` primary key | Existing PK conditions | PK value |
| VOLATILE | Single nonnegative `LONG`/`INT64` primary key | Existing PK conditions | PK value |

LOG and TAG ROWIDs use `0..UINT64_MAX-1`. Primary-key-based table ROWIDs use `0..INT64_MAX`. Zero is
valid; `UINT64_MAX` and negative primary-key values are not valid ROWIDs.

### LOG queries

LOG supports ROWID range queries and ordering. Use ROWID instead of `_ARRIVAL_TIME` when a query must
identify one exact row.

```sql
SELECT ROWID, message
  FROM app_log
 WHERE ROWID >= ? AND ROWID < ?
 ORDER BY ROWID;
```

`ROWID IN (...)` is not supported.

### TAG queries

TAG supports only a single ROWID equality condition at the top level of `AND` predicates.

```sql
SELECT ROWID, name, time, value
  FROM sensor_tag
 WHERE ROWID = ?
   AND name = 'TAG-01';
```

TAG does not support ROWID range, `IN`, `OR`, ordering, deletion, rollup, or stat-result operations.

### TRANSACTION, LOOKUP, and VOLATILE tables

These table types expose a single nonnegative `LONG`/`INT64` primary key as ROWID, whether the key is
explicit or generated by `AUTO_INCREMENT`. TRANSACTION and LOOKUP persist rows and the next automatic
value across restart; VOLATILE does not. Only TRANSACTION supports explicit transactions.

### Joins, aggregation, and views

A join does not create one ROWID for the combined result. Select each required source alias explicitly.
Aggregation, `GROUP BY`, `DISTINCT`, and set operations do not generate a result ROWID. A view, CTE,
or inline view carries ROWID only when its inner SELECT includes it.

## Conditions for a generated ROWID

Do not use `INSERT ... RETURNING ROWID`. Supported SDKs expose the identifier from the execution
result of a successful single-row `INSERT ... VALUES`.

| Input path | Generated ROWID |
|---|:---:|
| Direct single-row `INSERT ... VALUES` | Yes |
| Single prepared INSERT | Yes |
| `INSERT ... SELECT` | No |
| Execute array, batch, or `executemany()` | No |
| Append API or append batch | No |
| Loader | No |
| UPSERT | No |
| Failed INSERT | No |

The generated ROWID belongs to a statement result. Machbase does not provide a SQL function that
returns the most recent identifier for an entire connection.

## SDK access

| SDK or tool | Accessor | No-value result |
|---|---|---|
| machsql | `SHOW LAST ROWID;` or `SHOW LASTID;` | `NULL` |
| Machbase SQLCLI | `SQLGetGeneratedRowID()` | `SQL_NO_DATA` |
| Standard ODBC | No standard generated-ROWID API | Not applicable |
| JDBC | `Statement.getGeneratedKeys()` | Empty ResultSet |
| Go `database/sql` | `Result.LastInsertId()` | Error |
| Native Go (`machgo`) | Not supported | Not applicable |
| Python | `cursor.lastrowid` | `None` |
| Node.js | Execution result `rowId` | Property absent |
| .NET 4.0/4.0-full and Universal .NET | `MachCommand.RowId` | `null` |

An execution object clears its previous ROWID when a new statement starts. Do not reuse an earlier
value after failure, batch, Append, or an INSERT that cannot return a ROWID.

### JDBC

```java
String sql = "INSERT INTO orders(item) VALUES(?)";
try (PreparedStatement statement = connection.prepareStatement(
         sql, Statement.RETURN_GENERATED_KEYS)) {
    statement.setString(1, "pump");
    statement.executeUpdate();

    try (ResultSet keys = statement.getGeneratedKeys()) {
        if (keys.next()) {
            RowId rowId = keys.getRowId("ROWID");
        }
    }
}
```

Check `DatabaseMetaData.supportsGetGeneratedKeys()`. Batch and Append return an empty generated-keys
ResultSet.

### Go database/sql

```go
result, err := db.ExecContext(ctx,
    "INSERT INTO orders(item) VALUES(?)", "pump")
if err != nil {
    return err
}

value, err := result.LastInsertId()
if err != nil {
    return err
}
rowID := uint64(value)
```

Convert the `int64` result to `uint64` to preserve the bit pattern of a LOG or TAG ROWID whose most
significant bit is set.

### Python

```python
cursor.execute(
    "INSERT INTO orders(item) VALUES(%s)",
    ("pump",),
)
row_id = cursor.lastrowid
```

`lastrowid` is a Python `int` or `None`. It remains `None` after `executemany()`.

### Node.js

```javascript
const [result] = await connection.execute(
  "INSERT INTO orders(item) VALUES(?)",
  ["pump"]
);

if (result.rowId !== undefined) {
  const rowId = result.rowId; // bigint
}
```

Use JavaScript `bigint`, not `number`, to preserve 64-bit precision.

## Lifetime and retries

Do not persist ROWID as a long-term business identifier. DELETE, rollback, recovery that discards a
row, export/import, and reinsertion invalidate it. LOG TRUNCATE and table recreation may allow an old
value to identify a different row.

If an INSERT succeeds but the network response is lost, retrying the same INSERT may create a
duplicate. Check a business key or another idempotency policy before retrying.
