# DBMS リファレンスのソースマニフェスト

`data/dbms-reference/` の JSON ファイルは、DBMS マニュアルの監査に使用する生成データです。
正規の NFX ソースチェックアウトから、登録済みの関数記述子、固定テーブルのスキーマ、
エラーを抽出します。登録されているだけでは、公開 API であることを保証しません。
エラー生成ツールは、韓国語・英語・日本語のエラー辞書ページでマーカーに囲まれた
完全カタログのブロックも管理します。その前後の説明、例、互換性の注意、原因、対処方法は
手作業で記述します。

NFX のリビジョンや対応するリファレンスページを変更したら、スナップショットと各言語の
エラーカタログのブロックを再生成してください。

```bash
python3 scripts/generate_dbms_reference_manifest.py \
  --nfx-root /path/to/nfx
```

CI やレビューでは、ファイルを変更せずに JSON やマニュアルのカタログブロックが古くなって
いないか確認できます。

```bash
python3 scripts/generate_dbms_reference_manifest.py \
  --nfx-root /path/to/nfx \
  --check
```

`has_korean_reference_heading` は、リファレンスの見出しだけに基づく限定的な網羅性の指標です。
`false` はレビュー対象であることを示し、マニュアル全体にその項目の記載がないという意味では
ありません。`listed_in_korean_reference` は、解析した `ERR_ID` が韓国語マニュアルに記載されて
いるかを示します。登録済みのすべてのエラーを公開カタログに載せるべきだという意味では
ありません。8.7.0 の公開カタログでは、`ERROR_CATALOG_EXCLUDED_CODES` にある廃止機能の
24 項目を除外しますが、ソースインベントリには保持します。この除外方針は、韓国語・英語・
日本語のカタログ生成に共通です。サーバーのエラーコード、シンボル、元のメッセージは翻訳
しません。エディション固有の記述子とプリプロセッサー条件は各マニフェストに残し、特定の
ビルド構成の動作をすべての構成で保証される仕様と誤認しないようにします。

関数の戻り値の型とサイズは、記述子での宣言です。実際の SQL の戻り値の型はバリデーターが
選択する場合があります。また、サイズ式は内部バッファーのサイズであり、利用者向けの
長さの上限ではありません。関数インベントリは `gRootOfFunctions` と `mNext` 形式の初期化子を
ソースレベルで推定して抽出します。両方のビルドからコンパイル済み記述子のダンプを取得せずに、
エディションのサポート仕様として使用してはいけません。静的な固定テーブルのマニフェストは、
メタデータビルダーと同じ規則で `_ARRIVAL_TIME`、条件付きの `HOSTNAME`、`_RID` を生成します。
実行時の `V$<TAG_TABLE_NAME>_STAT` ビューは、動的な名前のパターンとして別に記録します。
エラーメッセージの C 書式トークンは保持しますが、原因、対処方法、再試行の可否、対応
エディション、対応バージョンは推測しません。

`.msg` 字句解析器は、引用符で囲まれた文字列の外側にある `#`、`//`、`/* ... */` だけを
コメントとして扱います。`format_tokens` 配列はリテラルの `%%` を保持します。
`conversion_tokens` は変換トークンを格納しますが、引数リストではありません。幅と精度の
`*` が追加の引数を消費する場合があるためです。

独立したレビュー記録やブラウザー検証を含む日本語翻訳と生成サイトの検証については、
[日本語マニュアルの保守](JAPANESE_MANUAL.ja.md) を参照してください。
